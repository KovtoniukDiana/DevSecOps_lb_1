# Архітектура системи «Драконяча клініка»

Система складається з п'яти компонентів. Усі вони працюють з однією базою даних.

## Компоненти

| Компонент | Призначення |
|---|---|
| Картки пацієнтів | Вид істоти, вік, вага, власник, історія хвороб і лікування |
| Розклад прийомів | Запис до лікаря, вільні слоти, нагадування про візит |
| Облік процедур | Перелік «вогнетривких» процедур, обладнання і вимоги безпеки для персоналу |
| Користувачі й ролі | Ветеринар, адміністратор, власник істоти; права доступу за роллю |
| Сповіщення | Листи й повідомлення власникам про прийом та результати лікування |

## Потоки даних

1. Адміністратор створює картку пацієнта і прив'язує її до власника.
2. Власник або адміністратор записує істоту на прийом через розклад.
3. Ветеринар під час прийому вносить процедури та діагноз у картку.
4. Система надсилає власнику сповіщення про результат і наступний візит.

## Безпека

- Доступ до карток мають лише ветеринар і адміністратор клініки; власник бачить тільки свою істоту.
- Паролі та ключі зберігаються поза репозиторієм (файл `.env` у `.gitignore`).
- Усі вхідні дані від користувача перевіряються на сервері.
- Зміни потрапляють у `main` лише через pull request із рецензією та підписаними комітами.
- Резервні копії бази даних створюються щоденно й зберігаються окремо від основного сервера.
